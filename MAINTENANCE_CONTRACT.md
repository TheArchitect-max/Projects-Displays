1. Check current main SHA, tree and open PR count. Work on one branch only.
2. Review any actual project edition change, provenance and rights in its **own** private repository. Keep unaccepted releases out of the public product claim.
3. Approve the corresponding publication changes in canonical MyProjects. Freeze the exact public source SHA.
4. Update the frozen SHA in sync_snapshot.py, validate.py, CI and this document consistently. Change expected count/financial data only with a separately reviewed basis.
5. Mirror the entire public publication, never isolated generated factsheets, using the explicit --write option.
6. Validate the full source tree, 123 distinct identity mappings, 123 HTML presentations, 123 briefs, 123 four-page PDFs, 984 per-project EUR financial fields, dated FX conversion, all publicly linked pages, historic aliases, published totals and every public source-file SHA-256. Confirm the checks do not mutate source files.
7. Require exact-head test PASS, source-pinned CI SUCCESS and expected-SHA-protected merge. Verify main, tree and PR closure before another build.
8. On a mismatch, blocked source, unavailable CI credits, unreviewed rights or invalid release evidence, record HOLD and correct the same candidate branch. Do not substitute Colab PASS for GitHub Actions PASS.
